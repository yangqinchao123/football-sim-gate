# 硬框架 v3.2.1 · 门禁对齐补丁（2026-11-16）

> 性质：**v3.2 的补丁，不改原文**。v3.2 全文仍在 `framework/` 留档；本文件只写"机器门禁按什么口径判"，
> 冲突时以本补丁为准，并注明补的是哪一条。
> 触发来源：2026-11-16 三方审计（框架 v3.2 / 纪律 v1.2.0 / GitHub 门禁），四个可绕过点已由
> `gates/stage_gate.py` + `gates/regression_test.py` 机器化收口。

## 0. 目标校准（先写死，避免口径漂移）

**唯一目标：预测准确率**（方向命中、RPS、Brier、平局校准）。ROI／注码／余额不作为门禁判据，
相关规则保留但不参与过关判定。任何"为了出票而放宽判据"的改动，一律按违反本补丁处理。

## 1. 补 G5：全方向表不许有"免检方向"

v3.2 原文是「只输出 GRC PASS 的场，先给全方向表」——同一句内自相矛盾，实现层只管条数。
补丁口径：

- 全方向表必须覆盖早盘全部场次（含空仓场），每场 `dir` 必须以 **H/D/A 开头**（可带后缀标注，如 `H（让-4）`）。
- **非进票腿不得只填方向**，必须二选一：
  - `no_bet_gate` 判 `NO_BET`：`reasons` 非空，且方向表 `gate` 字段写明触发的 **N 码**（N1–N5/N4b）；
  - `no_bet_gate` 判 `ELIGIBLE` 却未进票：必须给 `reject.reason` + `reject.evidence`（防空口否决）。
- 机器位置：`chk_S5`。

## 2. 新增：预测锁定（先锁后看）

- 出表后立即执行 `python3 tools/lock_predictions.py <批次>`，写入 `_meta.locked_at` + `predictions_sha256`。
- `chk_S5` 校验锁定存在且指纹与内容一致；`chk_S11` 赛后复核指纹，**赛后改方向 = 本批命中率作废**。
- 锁定后更正只能走 errata + `--relock`（会追加 `history`，不覆盖旧指纹）。
- **准确率统计口径**：只统计已锁定批次的预测。`D42` 在机制落地前合并、无锁定，
  其 7 场方向**不计入准确率样本**（`GRANDFATHER_PRED_LOCK` 只豁免它一个，新批次不适用）。

## 3. 补 G4：`agrees` 不再是免对质通行证

v3.2 要求「红队无条件对立」，但旧 `chk_S7` 对 `verdict="agrees"` 跳过轮次校验——
全填 agrees、0 轮即可过闸。补丁口径：

- 任何条目（含 agrees）都须 `rounds >= 2`，且实际落 `round1`/`round2`；
- 两份产物都必须有 `agent` / `_agent` 署名，缺署名不受理；
- 状态机兼容三种记录形态：list、`items/clashes/records`、`{编号: 记录}`。

## 4. 补优先级：三个否决权谁先（原文未写）

准确率角度必须定序，按此执行：

1. **模型最高项**（纪律 R3）是默认结论；
2. **红队否决**优先于 owner 确认：同场独立模型 argmax 与主分析相反 → 不进票，无论差距多小；
3. **owner 改序**只能发生在①②之后，且必须附三要素（具名硬证据 / 可证伪条件 / 替代者检查）并落 errata；
   缺一即按纪律事故处理，门禁不认该确认。
- 说明：第 3 条的机器校验（改序记录）排在下一批落地，当前先按文本执行、由流程审计逐场核。

## 5. 本补丁未修（留档，避免误以为已解决）

- 事实层已进 S4（2026-11-16 第二批）：进票腿须有 `<批次>_fact_<场次>.json`（含 league/standings/form/source、
  双方榜单齐全）且 GRC 引用；伤停须有 `<批次>_injury_<场次>.json`（collected_at + confirmed/unconfirmed
  两名单），双源状态冲突未解决即 BLOCK。残留风险：卡片内容本身来自本地 CSV，CI 不重算，靠复盘抽查。
- **独立性仍是署名自证**：`agent` 字段由写文件的人填，无法证明隔离。属残余风险，靠流程审计兜。
- **平局校准表低端被钳到 0.15**（D41 E-01）：会系统性抬高平局概率，影响 H/D/A 与 RPS，待模型层修。
- 注码五项、ROI、余额类校验：按第 0 条不纳入门禁。
